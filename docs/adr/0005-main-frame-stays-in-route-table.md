# Host는 메인 프레임을 허용 출처·경로 표 밖으로 보내지 않고, 앱 밖으로는 `browser.open` Call로만 나간다

Host는 내비게이션 콜백과 `loadRequest` 직전에 같은 판정 함수로 메인 프레임 이동을 검사한다. 허용 출처이면서 경로 표에 있는 경로만 연다. 허용 출처라도 경로 표에 없으면(API, 업로드 파일 등) 막고 "열 수 없는 링크"라고 안내한다. 다른 http(s) 주소와 그 밖의 스킴(`intent:`, `tel:`, 커스텀 스킴, `data:` 등)은 막기만 하고 시스템 브라우저로 넘기지 않는다. 외부 링크는 Web의 링크 컴포넌트가 `browser.open {url}` Call로 요청한다. Host는 그 URL이 http(s)이고 Web 출처가 아닌지 다시 확인한 뒤 시스템 브라우저로 연다. 그래서 앱 밖으로 나가는 일은 우리 번들이 메인 프레임에서 명시적으로 요청했을 때만 일어난다. 경로 판정은 [ADR 0001](0001-web-screen-content-policy.md)에서 Web이 콘텐츠 속 링크에 하는 판정을 Host에서 한 번 더 하는 것이다. 이렇게 하면 Web 링크 렌더러에 버그가 있어도, 사용자가 올린 파일(스크립트가 든 SVG 등)이 메인 프레임에서 Web 출처로 열려 출처 검증을 통과하는 일이 없다.

## Considered Options

- **콜백이 다른 http(s) 이동을 시스템 브라우저로 넘긴다(흔한 방식)**: 구현이 단순하다. 하지만 리디렉션이나 스크립트가 일으킨 이동처럼 사용자가 누르지 않은 이동도 앱 밖으로 나간다.
- **출처만 검사한다**: Web 출처 안의 API·업로드 파일 주소가 메인 프레임에 문서로 열릴 수 있다.

## Consequences

- Web 출처의 문서 단위 이동은 모두 경로 표에 있어야 한다. 글쓰기(`/compose`)와 인증 경로처럼 딥링크로는 열지 않는 경로도 경로 표에 넣고, 딥링크로 열 수 없다고 표시한다. Next.js 클라이언트 이동(pushState)은 콜백을 거치지 않으므로 이 판정에 걸리지 않는다.
- "Bridge 없음" 상태에서는 외부 링크를 열 수 없다. Web은 이 경우 열 수 없다고 안내한다.
- 프레임은 이 판정의 대상이 아니다. Android에서는 콜백이 iframe 이동을 받지 못하므로, 프레임은 두 플랫폼 모두 Web의 CSP `frame-src`와 iframe `sandbox`로 막는다. 임베드가 메인 프레임을 이동시키거나 새 창을 여는 시도는 sandbox가 먼저 막고, Host 콜백이 두 번째로 막는다.
- URL을 받는 Call은 `browser.open` 하나뿐이다. 다른 Call은 id를 받고, Host가 자격 증명을 실어 요청을 보낼 주소는 Host 설정에서 만든다.
